# 실행 환경

## 환경
- 환경은 local, test, production 세 가지이고, production DB만 버리지 않음
- 환경마다 namespace를 하나씩 둠. 한 환경의 Pod가 다른 환경의 비밀값을 읽지 못함

## 설정
- 환경마다 달라질 수 있는 값은 코드가 아니라 설정값으로 둠
- 코드에서 환경 이름으로 분기하지 않음. 그 분기는 production에 올리기 전까지 실행되지 않음
  - `NODE_ENV`도 환경 이름으로 쓰지 않음. Node의 실행 모드일 뿐임
- 필수 설정값에는 기본값을 두지 않음. local 값이 production에서 조용히 쓰임
- 앱은 시작할 때 설정값을 검증하고 틀리면 시작하지 않음
- 접근을 허용하거나 데이터를 지우는 기능은 설정이 없으면 닫힌 쪽으로 동작함
- UI 설정값은 빌드할 때 번들에 들어감. production 값은 Cloudflare UI 프로젝트의 빌드 변수에 둠
  - 저장소와 helm values에는 UI의 production 값이 없음. 런타임 변수에 넣으면 번들에 들어가지 않음

## env 파일
- local과 test의 env 파일만 커밋함. 그 PC 밖에서 쓸 수 없는 값은 비밀값이 아님
- 어떤 env 파일을 읽을지는 실행 명령이 정함. 앱 코드가 환경 이름으로 파일 경로를 만들지 않음
- 개발 도구의 접속 정보는 앱의 env 파일에 넣지 않음

## 비밀값
- production 비밀값은 저장소에 두지 않고 AWS SSM Parameter Store에 환경마다 다른 경로로 둠
  - 암호화한 형태로도 저장소에 두지 않음. SealedSecret은 클러스터를 다시 만들면 모두 다시 암호화해야 함
- 클러스터는 External Secrets Operator로 비밀값을 가져와 Pod에 파일로 마운트하고, 앱은 파일에서 읽음
  - 환경 변수는 자식 프로세스에 물려지고 도구가 통째로 기록하기 쉬움
  - 앱이 AWS를 몰라서 local과 클러스터에서 같은 코드로 설정을 읽음
- 비밀값은 정의가 바뀔 때만 다시 가져옴. 바뀐 값이 사람이 정하지 않은 시점에 Pod로 들어가지 않음
- 같은 비밀값은 한 번만 두고, 그 값으로 만드는 다른 값은 template으로 만듦. 두 곳에 두면 한쪽만 바뀜
- 비밀이 아닌 값은 비밀값에 넣지 않음. 비밀값은 리뷰에서 무엇이 바뀌었는지 보이지 않음
- 환경마다 다른 비밀값을 쓰고, 비밀값을 로그와 오류 보고에 남기지 않음
- 브라우저와 플러그인에 들어가는 값은 비밀값이 될 수 없음

## 마이그레이션
- production 마이그레이션은 새 코드가 요청을 받기 전에 배포의 한 단계로 적용함. 실패하면 이전 버전이 계속 요청을 받음
- 마이그레이션은 롤아웃 동안 요청을 받는 이전 코드와 호환되게 만듦
  - 구조를 지우거나 이름을 바꿀 때는 추가, 코드 전환, 삭제를 서로 다른 배포로 나눔
  - 이전 코드 때문에 남기는 것은 DB 구조뿐임. 새 코드에서 필요 없어진 코드는 코드 전환 배포에서 지움
  - 남긴 DB 구조는 schema 선언에 `todo:` 주석으로 지울 배포와 이유를 적음
    - 이유: 다음 배포에서 지울 대상을 코드 검색으로 찾을 수 있음
