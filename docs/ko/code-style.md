# 코드 모양

## 함수 몸통의 빈 줄
- 빈 줄은 코드의 문단 경계임. 하는 일이 바뀌는 곳에 빈 줄을 하나 둠
  - 읽는 사람은 빈 줄로 단계를 찾고, 빈 줄 사이의 줄을 한 덩어리로 읽음
- 다음 위치는 하는 일이 바뀌는 곳임
  - 입력 꺼내기와 검사가 끝나고 본 작업이 시작되는 곳
  - 계산이 끝나고 저장, 전송 같은 부수 효과가 시작되는 곳
  - 앞의 단계들이 끝나고 결과를 돌려주는 `return`
  - 테스트의 준비, 실행, 확인 사이
    - 여러 단계를 차례로 확인하는 테스트는 단계마다 실행과 그 확인을 한 문단으로 묶고, 단계 사이에 빈 줄을 둠
- 한 단계 안에는 빈 줄을 두지 않음. 예: 같은 값을 만드는 연속한 대입, 연속한 `expect`
  - 단계 안에 빈 줄이 있으면 진짜 경계가 묻힘
- Prettier와 lint는 이 규칙을 검사하지 않음. 쓰는 사람과 리뷰가 지켜야 함

## 분기 순서와 조건
- 함수의 마지막 `return`은 정상 흐름임. early return으로 먼저 빠져나가는 분기는 특수한 경우여야 함
  - 특수한 경우: 잘못된 입력, 없는 값, 권한 없음, 한도에 닿음처럼 기본 동작이 아닌 경우
  - 정상 흐름을 먼저 빼면, 끝까지 읽은 사람이 특수한 경우를 기본 동작으로 읽음
- 어느 쪽이 정상 흐름인지는 그 경우가 함수의 기본 동작인가로 정함. 대부분 더 자주 일어나는 쪽과 같고, 다를 때는 기본 동작을 따름
- 조건은 긍정형으로 씀. 예: `if (count !== max) return ...` 대신 `if (count === max) { ... }`
  - 부정형 조건은 읽을 때 한 번 더 뒤집어야 함
  - 특수한 경우가 "값이 없음"이면 `!x`가 그 경우를 그대로 말함. 예: `if (!apiToken) throw ...`
- 두 분기가 모두 그 자리에서 끝나면(반환 또는 throw) 긍정형 조건의 분기를 먼저 둠
  - 뒤에 이어지는 본문이 없으므로 순서가 기본 동작을 잘못 전하지 않음
- 값의 종류에 따라 동작이 나뉘면 `switch`로 씀. 예: `switch (credential.type)`
  - 동작이 종류별로 나뉜다는 것이 모양으로 드러남
