# Ingestion 도메인

## 용어

- 임베딩 대상 본문: library가 sync job과 함께 넘겨주는 source의 본문이다.
  - source, 본문, sync job은 [library 도메인](./library.md)에 정의한다.
- 청크(chunk): 임베딩 대상 본문을 검색 단위로 나눈 조각이다. 본문 안의 순서대로 번호를 가진다.
- 청크 임베딩: 청크 하나와 그 청크의 벡터다.
- source 임베딩(`SourceEmbedding`): source 하나에 속한 청크 임베딩 전체다.
- 임베딩 모델: 벡터를 만드는 모델이다. 모델마다 벡터의 차원이 정해져 있다.
- 임베딩 workflow: sync job 하나를 처리하는 작업 묶음이다.
  - 청크마다 임베딩하는 작업과, 결과를 모아 저장하는 마무리 작업으로 이루어진다.

## 임베딩 대상 규칙

- 임베딩 대상은 source의 본문이다. 제목과 frontmatter는 임베딩하지 않는다.
- 청크는 한 가지 주제를 담을 만큼 짧게 자른다.
  - 청크가 길면 벡터 하나에 여러 주제가 섞여 검색 정확도가 떨어진다.
  - 청크가 길면 작은 임베딩 모델에서 처리 시간이 입력 길이보다 빠르게 늘어 timeout이 잦아진다.
- 인접한 청크는 경계 부분을 일부 겹친다.
  - 문장이나 문단이 청크 경계에서 잘려도 앞뒤 문맥을 잃지 않게 한다.
- 청크는 문단, 줄, 단어 경계를 차례로 우선해서 자른다. 그래도 길면 글자 수로 자른다.

## 임베딩 모델 규칙

- 한 시점에 허용하는 임베딩 모델은 하나다.
  - 모델이 다르면 벡터를 서로 비교할 수 없다. 모델이 섞이면 의미 검색 순위가 무의미해진다.
- 한 source 임베딩 안의 청크 임베딩은 모두 같은 모델로 만든다.
  - 다른 모델의 결과가 섞인 workflow 결과는 저장하지 않고 실패로 처리한다.

## 저장 규칙

- source 하나에 source 임베딩은 하나다. 이전 버전의 임베딩은 보관하지 않는다.
- 새 source 임베딩은 이전 source 임베딩을 통째로 교체한다.
  - 검색이 서로 다른 버전의 청크를 섞어 보지 않게 한다.
- 저장된 source 임베딩보다 나중에 만들어진 sync job의 결과만 저장한다. 먼저 만들어진 sync job의 결과는 버린다.
  - 내용이 빠르게 두 번 바뀌면 두 workflow가 함께 돌고, 끝나는 순서는 만들어진 순서와 다를 수 있다.
    끝난 순서대로 저장하면 이전 내용의 임베딩이 최신 내용의 임베딩을 덮어쓴다.
  - 새 sync job이 생길 때 이전 workflow를 취소하는 것은 비용을 줄이는 최적화일 뿐, 이 규칙을 대신하지 않는다.
    취소가 이미 끝나 가는 workflow에 늦게 닿을 수 있다.
- 임베딩 대상 본문이 비어 있으면 청크 없이 정상 완료하고, 이전 source 임베딩을 지운다.
  - 내용이 없는 문서에는 검색할 내용이 없다. 실패로 처리하면 동기화 클라이언트가 끝없이 재시도한다.
  - 이전 source 임베딩을 남기면 본문을 비운 문서가 이전 내용으로 검색된다.
  - 청크가 없으면 어느 sync job의 결과인지도 남지 않는다.
    본문을 비운 뒤에 비우기 전 내용의 workflow가 늦게 끝나면 그 결과가 저장된다.
    드물고 다음 편집에서 바로잡히므로 감수한다.
- 청크 결과가 하나라도 빠진 workflow 결과는 저장하지 않고 실패로 처리한다.
  - 이때 이전 source 임베딩은 그대로 남는다. 일부만 교체된 source 임베딩은 없다.
- source 임베딩 저장과 완료 통지는 함께 성공하거나 함께 실패한다.
  - 저장했는데 library가 모르거나, library는 완료로 아는데 저장되지 않은 상태를 만들지 않는다.

## 실패와 재시도 규칙

- 재시도는 청크 단위로 한다. 이미 성공한 청크는 다시 임베딩하지 않는다.
- 재시도 주체는 청크 작업 하나다. 청크 작업 안의 임베딩 호출은 따로 재시도하지 않는다.
  - 재시도 주체가 여러 겹이면 재시도 횟수가 곱해진다.
- 청크 하나가 재시도를 모두 소진하면 그 sync job을 실패로 통지한다.
  - 재시도가 남아 있는 동안에는 실패로 통지하지 않는다.
- 실패한 sync job을 ingestion이 다시 시작하지 않는다.
  - 재시도는 library의 동기화 규칙에 따라 새 sync job으로 들어온다.
