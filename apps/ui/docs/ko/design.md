# UI 디자인 컨벤션

## 기준
- 이 문서와 `design-tokens.json`이 시각 방향의 기준임. 외부 디자인 도구를 기준으로 삼지 않음
- token은 구현이 실제로 쓰는 것만 둠. 쓰이지 않는 token은 어떤 값이 화면을 정하는지 가림
- 효과, motion, breakpoint 값은 쓰는 곳을 가리킬 수 있을 때만 더함

## 톤
- monochrome palette에 accent 색 하나만 씀. 상태는 색을 늘리지 않고 모양과 글자로 나타냄
- 어두운 terminal 톤은 header, landing, code fence에만 씀
- 장식은 header와 landing에만 두고 나머지 화면은 글자와 선만으로 짬. 장식이 한 곳에 모여야 앱의 정체성으로 읽힘
- 예외로 landing 터미널 출력은 상태 색 2개를 씀. amber는 오류, 초록은 끝난 동작임. 오류가 accent와 섞여 보이지 않게 붉은 계열을 피함
- 예외로 상세 화면의 AI 요약 콜아웃은 밝은 화면에서 면(`accent-tint`)을 씀
  - AI가 쓴 요약이 vault 원문으로 읽히지 않아야 함. 선만 쓰면 바로 아래 본문 구분선과 섞임
  - 면은 이 콜아웃 하나에만 씀
- 예외로 본문 callout은 type을 색 3개로 나눔. 기본은 `text-muted`, 강조는 `accent-strong`, 주의는 `caution`
  - 독자가 구분할 것은 참고, 권함, 조심 세 가지임. Obsidian type 13개를 색 13개로 나누면 palette가 무너짐
  - 주의는 amber로 씀. 붉은 계열은 accent와 섞여 보임
- 터미널 프롬프트의 사용자 부분, 커서, LLM 답 앞의 AI 아이콘은 accent로 씀. 링크는 primary로 씀. 소유자는 색이 아니라 이름과 `#`으로 구분함
- 터미널 안 출력은 LLM 답을 포함해 mono 글꼴 하나로 씀. 글꼴이 바뀌면 그 부분만 다른 화면처럼 읽힘

## 화면 구성
- post 목록은 글마다 메타 줄과 제목을 차례로 놓음. 메타 줄은 날짜와 조회수를 mono로 씀
  - 제목은 자르지 않고 줄바꿈함. 행이 여러 줄이므로 한 줄에 맞출 까닭이 없음
- 넓은 화면에서는 연도를 목록 왼쪽 여백에 두고 스크롤을 따라 붙임. 목록 칸은 좁은 화면과 같은 폭을 씀
- 검색 유사도는 행 안에 둠. 화면 폭에 따라 숨는 자리에 두지 않음
- 목록에서 글 내용을 미리 보여 줄 때는 목록 응답의 값만 씀. 상세 API는 조회수를 올림
- 상세 화면의 header는 본문보다 크게 보이지 않게 함
- 상세 화면은 AI 요약 콜아웃과 질문 줄을 제목 블록 안, 본문 구분선 위에 둠
  - 구분선이 AI가 쓴 글과 원문을 나눔
- AI 요약은 줄 수를 정하지 않음. 콜아웃과 목록 행은 받은 줄을 자르지 않음
- 요약이 pending이나 failed여도 자리를 숨기지 않고 문구만 바꿈. 목록과 상세가 같은 문구를 씀

## 색과 글꼴
- 대비가 낮은 accent는 밝은 배경에서 큰 글자와 선에만 씀
- 밝은 배경과 어두운 surface의 낮은 강조 색은 서로 대체하지 않음. 상대 배경에서 대비가 무너짐
- 넓은 자간은 대문자 label에만 씀. 대문자가 아닌 문구에서는 폭만 먹음

## 본문 기호
- 본문은 요소를 vault 원문의 markdown 기호로 구분함. 예: heading의 `#`, 인용의 `>`, wiki link의 `[[ ]]`
  - 기호는 글자라서 장식을 header와 landing에 모으는 규칙을 깨지 않음. 글이 vault 노트에서 왔다는 것도 함께 드러남
  - 새 요소를 더할 때도 색이나 선보다 원문 기호를 먼저 씀
- 기호는 복사한 글과 스크린 리더가 읽는 글에 들어가지 않음
  - 기호는 화면을 위한 표시임. 복사한 글에 섞이면 원문과 다른 글이 됨
- 넓은 화면에서는 기호를 왼쪽 여백에 걸어 본문 글자의 왼쪽 끝을 맞춤
  - 다른 블록을 담는 요소는 여백에 걸지 않고 들여 씀. 예: 인용. 안에 든 목록과 code fence는 기호가 없어 들여쓰기로만 인용에 속함이 보임
  - 예외로 heading은 얕은 단계일수록 본문보다 왼쪽에서 시작함. 기호는 heading을 따라 움직임
  - 위치가 단계를 함께 나타내므로 heading 크기 차이를 작게 둘 수 있음. 크기만으로 단계를 나누면 `#`가 글 제목 크기에 가까워짐
- 중첩 목록은 `-` 대신 tree 연결선으로 부모와 이음
  - 깊이가 셋을 넘으면 들여쓰기만으로는 어느 부모에 속하는지 흐려짐. 맨 바깥 `-`와 번호는 원문 기호로 남김
- 예외로 callout은 `>` 대신 type 색의 왼쪽 선으로 범위를 보임. 면은 쓰지 않음
  - 글자 label만으로는 type이 약하게 보임. 선은 callout 높이 전체에 색을 보여 줌
  - `[!type]` 표시는 제목 줄 앞의 대문자 mono label로 바꿈. 원문 표시를 그대로 두면 제목과 섞여 읽힘
- `-`로 접힌 callout은 접힌 채로 그림. 제목 줄 앞 chevron이 접힘 상태를 보임

## 코드 펜스
- token은 색이 아니라 밝기 단계로 나눔. palette에 다색 theme을 쓸 색이 없고, 색을 구분하지 못해도 층위가 남음
- 복사 결과는 아이콘과 `role="status"`로 알림. 복사는 화면에 결과를 남기지 않고 실패할 수도 있음

## 목차
- 목차는 본문 옆에 여백이 충분한 폭에서만 보이고 항상 펼쳐 둠
  - 좁은 폭용 접힌 목차는 hover 없는 기기에서 본문을 덮어서 뺐음
- 목차 항목은 한 줄만 씀. 목차는 제목 전문이 아니라 섹션의 개수와 깊이를 보여 줌

## 반응형
- 기본 스타일은 가장 좁은 화면 기준으로 쓰고 넓어질 때만 더함. `max-width`로 되돌리지 않음
- 지원 하한은 320px임
- 크기 문제는 breakpoint보다 상한선으로 먼저 풂. 상한선은 breakpoint 안에 넣지 않음
  - 상한은 화면 크기와 무관하게 항상 참이어야 함
- 두 기준 중 하나를 고르는 위치는 `min()`, `max()`, `clamp()`로 계산함. 기준을 바꿔도 전환점이 따라옴
- breakpoint는 형태가 바뀌는 곳에만 쓰고, 기기 이름이 아니라 그 폭에서 하는 일로 부름
- breakpoint 값이 다른 token에서 유도되면 그 token을 바꿀 때 다시 계산함
- container query는 재사용 컴포넌트를 폭이 다른 두 번째 자리에 놓을 때 도입함

## Overflow
- 페이지 자체에는 가로 스크롤이 생기지 않아야 함
- 폭을 줄일 수 없는 콘텐츠는 자기 스크롤 컨테이너에 가둠
- 본문은 긴 단어를 접고, 한 줄로 훑는 목록은 줄을 늘리지 않고 자름. 자른 전문은 `title`에 남김
- 긴 값이 들어가는 flex, grid 항목에는 `min-w-0`을 줌. 줄바꿈만으로는 항목이 줄지 않음
