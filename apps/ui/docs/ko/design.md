# UI 디자인 컨벤션

## 기준
- 이 문서와 `design-tokens.json`이 시각 방향의 기준임. 외부 디자인 도구를 기준으로 삼지 않음
- token은 구현이 실제로 쓰는 것만 둠. 쓰이지 않는 token은 어떤 값이 화면을 정하는지 가림
- 효과, motion, breakpoint 값은 쓰는 곳을 가리킬 수 있을 때만 더함

## 톤
- monochrome palette에 accent 색 하나만 씀. 상태는 색을 늘리지 않고 모양과 글자로 나타냄
- 어두운 terminal 톤은 header, landing, code fence에만 씀
- 장식은 header와 landing에만 두고 나머지 화면은 글자와 선만으로 짬. 장식이 한 곳에 모여야 앱의 정체성으로 읽힘
- 예외로 landing 터미널 출력은 상태 색 2개를 씀. amber는 오류, 초록은 끝난 동작임. 오류가 accent와 섞여 보이지 않게 붉은 계열을 피함
- 예외로 상세 화면은 머리와 끝에 화면 폭 전체의 옅은 판(`plate`)을 둠
  - 판 위에는 vault 원문이 아닌 것만 둠. 머리판에는 AI가 쓴 요약, 끝판에는 시리즈와 관련 프로젝트 안내가 들어감
  - 판의 경계가 원문의 시작과 끝을 나눔
  - 밝은 화면의 면은 이 두 판과 본문 callout에만 씀
- 예외로 목록의 고른 프로젝트 탭은 선을 끊고 파인 옅은 홈으로 표시함. 홈 안쪽에 위와 옆 그림자를 씀
  - 고른 상태를 색이 아니라 모양으로 보임
  - 안쪽 그림자는 다른 층이 아니라 눌린 칸을 뜻함
- 예외로 상세 화면의 질문 줄은 본문 위에 떠 있어서 그림자를 씀
  - 그림자가 질문 줄이 본문과 다른 층임을 알림. 본문 안의 요소에는 그림자를 쓰지 않음
- 예외로 본문 callout은 type을 색 3개로 나눔. 기본은 `text-muted`, 강조는 `accent-strong`, 주의는 `caution`
  - 독자가 구분할 것은 참고, 권함, 조심 세 가지임. Obsidian type 13개를 색 13개로 나누면 palette가 무너짐
  - 주의는 amber로 씀. 붉은 계열은 accent와 섞여 보임
  - callout은 type 색을 6%로 옅게 깐 면과 원 아이콘으로 나타냄. 면은 범위를, 아이콘은 type을 제목보다 먼저 보임
- 터미널 프롬프트의 사용자 부분, 커서, LLM 답 앞의 AI 아이콘은 accent로 씀. 링크는 primary로 씀. 소유자는 색이 아니라 이름과 `#`으로 구분함
- 예외로 관련 프로젝트 로고는 목록과 상세 끝판 모두 About 화면과 같은 원색으로 씀
  - 로고는 프로젝트를 알아보는 표지임. 색을 빼면 About에서 본 로고와 다른 것처럼 보임
- 터미널 안 출력은 LLM 답을 포함해 mono 글꼴 하나로 씀. 글꼴이 바뀌면 그 부분만 다른 화면처럼 읽힘

## 화면 구성
- post 목록은 글마다 제목과 요약을 놓음. 날짜와 조회수는 목록에 쓰지 않고 연도로 묶지도 않음. 순서는 최신 발행순임
  - 제목은 자르지 않고 줄바꿈함. 행이 여러 줄이므로 한 줄에 맞출 까닭이 없음
  - 메타 줄은 쓸 것이 있을 때만 제목 위에 mono로 씀. 관련 프로젝트는 로고와 이름, 시리즈 글은 시리즈 이름과 위치(`2 / 5`), 검색 중에는 일치율임
    - 관련 프로젝트와 시리즈가 함께 있으면 `프로젝트 · 시리즈` 차례로 씀. 화면이 모르는 프로젝트 값은 없는 것처럼 다룸
  - 시리즈 이름이 길면 한 줄로 자르고 위치는 자르지 않음
- 목록 위의 탭 줄로 관련 프로젝트를 거름. 탭이 넘치면 줄을 바꾸고 줄마다 밑선을 그음. 고른 프로젝트는 주소에 남음
  - 탭 줄 끝의 Search를 누르면 그 자리가 검색 줄로 바뀜. Enter로 찾으면 거르기를 풀고, 찾기 전에 닫으면 고른 탭으로 돌아감
  - 탭 줄과 검색 줄은 같은 자리를 나눠 씀. 머리 높이는 둘 중 큰 쪽이라 열고 닫아도 목록이 움직이지 않음
- 검색 유사도는 행 안에 둠. 화면 폭에 따라 숨는 자리에 두지 않음
- 상세 화면의 header는 본문보다 크게 보이지 않게 함
- 상세 화면은 AI 요약을 머리판 안에 두고, 질문 줄은 화면 아래 가운데에 띄움
  - 질문과 답이 늘어도 머리가 자라지 않음. 제목에서 본문으로 이어지는 흐름이 끊기지 않음
  - 펼친 대화는 modal이 아님. 카드 밖을 누르거나 `Esc`를 누르면 접히고, 본문 스크롤과 click을 막지 않음
- 상세 화면의 시리즈는 제목 위 한 줄과 본문 끝 목록으로 보임. 이전·다음 버튼과 시리즈 페이지는 두지 않음
  - 제목 위 줄은 시리즈 이름과 위치(`2 / 5`)만 씀. 이름이 길면 한 줄로 자르고 위치는 자르지 않음
  - 끝 목록은 시리즈 이름을 항목보다 크게 씀. 지금 글은 accent 색과 굵기로만 표시하고 글자 표시를 붙이지 않음
- 상세 화면의 끝판은 시리즈 목록 다음에 관련 프로젝트를 둠. 둘 다 없으면 끝판을 두지 않음
  - 관련 프로젝트는 label, 로고와 이름, tagline만 씀. 이름은 About의 프로젝트 화면으로 가는 링크임
  - 끝판은 페이지 끝까지 이어짐. 질문 줄은 판 위에 뜸
- 좁은 화면의 돌아가기는 메타 줄과 같은 글자 링크로 씀. 아이콘 칸이 제목을 아래로 밀지 않음
- AI 요약은 줄 수를 정하지 않음. 상세 요약과 목록 행은 받은 줄을 자르지 않음
  - 상세 요약과 목록 행은 두 줄 이상일 때만 번호를 붙임. `01` 하나만 있으면 다음 줄이 빠진 것처럼 보임
  - 목록 행은 번호 앞에 AI 별을 둠. 별이 없으면 한 줄 요약이 본문 발췌처럼 보임
    - 넓은 화면에서는 별을 왼쪽 여백에 걸어 요약 첫 글자를 제목 왼쪽 끝에 맞춤. 본문 기호를 여백에 거는 규칙과 같음
  - 요약 번호는 muted로 씀. accent는 별에만 둠. 번호까지 accent면 목록의 붉은 점이 요약 줄 수만큼 늘어남
- 요약이 pending이나 failed여도 자리를 숨기지 않음. failed는 목록과 상세가 같은 문구를 씀
  - pending일 때 상세는 요약 줄 자리에 막대를 보여 주고, 문구는 화면 낭독기에만 남김. 목록 행은 막대 둘 자리가 없어서 문구를 보여 줌
- 데이터를 기다리는 표시는 header 프롬프트에만 둠. 본문은 기다리는 동안 원래 틀만 남기고 비워 둠
  - AI 요약 pending은 요청을 기다리는 상태가 아니라 글의 상태임. 그래서 이 규칙에 들지 않음
  - header는 sticky라서 첫 로드와 다음 페이지 로드가 같은 자리에 보임. 본문에도 표시를 두면 같은 상태가 두 곳에 보임
  - 200ms 안에 끝난 요청은 표시하지 않음. 잠깐 나타났다 사라지는 표시가 응답을 더 느리게 보이게 함
  - 예외로 목록의 프로젝트 탭을 바꾸면 응답이 올 때까지 이전 행을 흐리게 남겨 둠. 200ms 안에 온 응답에는 흐리지 않음
    - 목록을 비우면 페이지 높이가 줄었다가 다시 늘어남. 탭을 누르는 동안 탭 줄이 화면에서 밀려남

## 색과 글꼴
- 대비가 낮은 accent는 밝은 배경에서 큰 글자와 선에만 씀
- 밝은 배경과 어두운 surface의 낮은 강조 색은 서로 대체하지 않음. 상대 배경에서 대비가 무너짐
- 넓은 자간은 대문자 label에만 씀. 대문자가 아닌 문구에서는 폭만 먹음

## 본문 기호
- 본문은 heading에만 vault 원문 기호 `#`를 남김. 나머지 요소는 기호 대신 모양으로 구분함
  - 인용은 serif 글자와 걸린 따옴표, 구분선은 `⁂`, wiki link는 일반 링크와 같은 밑줄로 씀
  - 원문 기호를 문장마다 두면 링크와 인용이 많은 글에서 기호가 글보다 먼저 읽힘
- 기호와 표시는 복사한 글과 스크린 리더가 읽는 글에 들어가지 않음
  - 기호는 화면을 위한 표시임. 복사한 글에 섞이면 원문과 다른 글이 됨
- 넓은 화면에서는 heading만 본문 칸 밖으로 내어 씀. 목록 점, 할 일 표시, 인용 따옴표는 칸 안에 둠
  - 얕은 단계일수록 4px씩 더 왼쪽에서 시작함(16 / 12 / 8 / 4px). 계단이 크면 heading마다 왼쪽 끝이 흔들림
  - `#`는 제목 글자의 0.8배로 씀. 오른쪽 끝은 본문 왼쪽 끝에서 32px 앞의 한 세로선에 맞춤. 계단을 따라 움직이면 기호 자리가 단계마다 달라 보임
  - 넓은 화면의 `#`는 그 섹션이 강조될 때만 보임. 좁은 화면은 hover가 없으므로 제목 앞에 늘 둠
- 상세 머리판의 내용은 넓은 화면에서 본문 칸보다 양쪽 24px 넓게 씀. 첫 heading이 글 제목보다 왼쪽에서 시작하지 않음
- 링크는 늘 옅은 밑줄(`accent-strong` 40%)을 둠. 링크 색과 본문 색의 대비가 3:1에 못 미쳐 색만으로는 링크를 찾기 어려움
- 중첩 목록은 tree 연결선으로 부모와 이음. 맨 바깥 항목은 `-` 대신 작은 점으로 씀. 번호 목록은 번호를 남김
  - 깊이가 셋을 넘으면 들여쓰기만으로는 어느 부모에 속하는지 흐려짐
- callout은 아이콘과 제목을 한 줄에 두고, 내용은 제목 글자에 맞춰 들여 씀
  - `[!type]` 표시는 아이콘으로 바꾸고, type 이름은 스크린 리더에만 남김
- `-`로 접힌 callout은 접힌 채로 그림. 제목 줄 오른쪽 끝의 chevron이 접힘 상태를 보임
  - chevron을 앞에 두면 접힌 callout만 제목이 오른쪽으로 밀림

## 섹션 강조
- 제목에 hover하면 그 섹션 밖의 글자를 흐림. 섹션은 제목부터 같은 단계 이하의 다음 제목 전까지임
  - 선이나 면을 더하지 않고 범위를 보임. 범위 밖이 물러나서 범위가 면처럼 읽힘
  - 강조한 섹션의 제목 글자와 기호는 accent 계열로 바뀜
- 제목을 누르면 강조를 고정함. 다른 제목을 누르면 고정이 옮겨 가고, 제목 밖을 누르거나 `Esc`를 누르면 풀림
  - hover가 없는 기기는 누르기로만 강조함
  - 글자를 드래그해 선택한 동작은 누르기로 보지 않음. 고정한 섹션을 복사할 수 있어야 함
- 흐리기는 늦게 시작하고, 풀기는 천천히 돌아옴
  - 마우스가 제목을 스쳐 지날 때 본문 전체가 깜빡이면 안 됨
- 질문 답의 근거 태그를 누르면 그 섹션으로 가면서 강조를 고정함. 제목을 누른 것과 같은 결과임

## 코드 펜스
- token은 색이 아니라 밝기 단계로 나눔. palette에 다색 theme을 쓸 색이 없고, 색을 구분하지 못해도 층위가 남음
- 복사 결과는 아이콘과 `role="status"`로 알림. 복사는 화면에 결과를 남기지 않고 실패할 수도 있음

## 반응형
- 기본 스타일은 가장 좁은 화면 기준으로 쓰고 넓어질 때만 더함. `max-width`로 되돌리지 않음
- 지원 하한은 320px임
- 크기 문제는 breakpoint보다 상한선으로 먼저 풂. 상한선은 breakpoint 안에 넣지 않음
  - 상한은 화면 크기와 무관하게 항상 참이어야 함
- 두 기준 중 하나를 고르는 위치는 `min()`, `max()`, `clamp()`로 계산함. 기준을 바꿔도 전환점이 따라옴
- breakpoint는 형태가 바뀌는 곳에만 쓰고, 기기 이름이 아니라 그 폭에서 하는 일로 부름
- breakpoint 값이 다른 token에서 유도되면 그 token을 바꿀 때 다시 계산함
- container query는 재사용 컴포넌트를 폭이 다른 두 번째 자리에 놓을 때 도입함

## Overflow
- 페이지 자체에는 가로 스크롤이 생기지 않아야 함
- 폭을 줄일 수 없는 콘텐츠는 자기 스크롤 컨테이너에 가둠
- 본문은 긴 단어를 접고, 한 줄로 훑는 목록은 줄을 늘리지 않고 자름. 자른 전문은 `title`에 남김
- 긴 값이 들어가는 flex, grid 항목에는 `min-w-0`을 줌. 줄바꿈만으로는 항목이 줄지 않음
